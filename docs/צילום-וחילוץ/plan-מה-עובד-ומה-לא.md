# צילום חשבונית וחילוץ מידע — מה עובד ומה לא

> תיאור מדויק של תת-המערכת **צילום → חילוץ → בדיקה → אישור**, נכון למצב הקוד היום
> (ולא לפי התיעוד הישן, שמפגר). מכסה **רק** את הצילום והחילוץ — לא את ייבוא קטלוג-העל
> (מוזכר רק היכן שהחילוץ תלוי בו).

---

## 1. הזרימה מקצה-לקצה

```
📱 מצלמת ה-OS → סינון חדות (בדפדפן) → העלאה → טיוטה (invoice_drafts)
     → חילוץ AI (Claude, בקשה אחת) → נרמול+אימות (offline) → מסך בדיקה (אדם מאשר, תמיד)
     → אישור → יצירת חשבונית  *או*  צירוף לחשבונית קיימת
```

| שלב | נתיב | פונקציית שירות | מסך |
|---|---|---|---|
| מסך צילום | `GET /scan` | — | `views/scan/capture.ejs` + `public/scan-capture.js` |
| העלאה | `POST /scan/upload` | `createDraft` | client `upload()` |
| מסך טיוטה | `GET /scan/:id` | `getDraft` | `views/scan/show.ejs` (3 מצבים) |
| הפעלת חילוץ | `POST /scan/:id/process` | `processDraft` | fetch+poll |
| סקר סטטוס | `GET /scan/:id/status.json` | — | poll |
| שמירת עריכות | `POST /scan/:id/save` | `saveDraftEdits` | טופס הבדיקה |
| אישור → חשבונית/צירוף | `POST /scan/:id/approve` | `approveDraft` → `matchingInvoice` | — |
| חילוץ מחדש | `POST /scan/:id/reprocess` | `resetForReprocess` | — |
| רשימת ממתינות | `GET /scan/pending` | `listPending` | `views/scan/pending.ejs` |

**מצבי טיוטה:** `uploaded → processing → needs_review` (או `failed`) `→ committed`.
טיוטה שאושרה = תיעוד הביקורת של החשבונית — לא ניתנת יותר לעריכה/מחיקה/חילוץ-מחדש.

## 2. מה **עובד** (מבוסס קוד)

### צילום (בצד הלקוח)
- **מצלמת ה-OS היא נתיב הצילום** (`<input capture="environment">`) + בחירת קובץ/גלריה/PDF.
  אין יותר סורק-מצלמה בתוך האפליקציה (ראה §4). הסיבה: הבעלים מדד שצילום OS פשוט
  (אוטופוקוס/HDR/הפחתת-רעש של המכשיר) נותן קלט טוב יותר מפריים שנתפס ב-`getUserMedia`.
- **סינון חדות — מזהיר, לא חוסם.** ציון חדות = שונות הלפלסיאן חלקי הניגודיות של התמונה
  (יחס שמבטל תאורה וצפיפות-דפוס, כך שסף אחד עובד גם ב-12MP וגם ב-3MP). סף `SHARP_MIN = 0.25`,
  מכויל על צילום חשבונית אמיתי. עמוד מטושטש → מסגרת אדומה + "צלם שוב" + אזהרת טקסט,
  אבל **ההעלאה עדיין מותרת**. בדיקה נועלת את הסף ואת זהות שני עותקי המחשב.
- **ריבוי עמודים בסדר הנכון:** המקום במערך העמודים נתפס *לפני* הפענוח האסינכרוני, כך
  שהעמודים מגיעים בסדר הבחירה (תיקון הבאג "3 עמודים התהפכו").
- **תיקון EXIF:** תמונות מיובאות מפוענחות עם `imageOrientation: 'from-image'` — כי ה-API
  לא קורא מטא-דאטה, האוריינטציה חייבת להיות "צרובה" בפיקסלים (תיקון צילומי אנדרואיד בשכיבה).
- **הקטנה חכמה:** אם התמונה כבר ישרה, JPEG, וקטנה מהסף — **המקור נשמר as-is** (בלי דחיסה
  שנייה שמוסיפה ארטיפקטים). אחרת ממירים ל-JPEG. הקצה הארוך מוגבל ל-1800px (המנוף העיקרי לעלות).
- **מגבלות והגנות:** עד 8 עמודים, 10MB לקובץ, 18MB סה"כ (נבדק לפני ההעלאה האיטית בנייד),
  פס-התקדמות אמיתי, `store_id` נבדק מול ההרשאות בשרת.

### חילוץ (AI)
- **מודל אחד, בקשה אחת לחשבונית:** `@anthropic-ai/sdk`, מודל `claude-opus-5` (ניתן להחלפה
  ב-env). כל העמודים = חשבונית אחת, ממוזגים.
- **פלט מובנה (JSON Schema):** כותרת (ספק, ח.פ, טלפון, מספר חשבונית, מספר הקצאה, תאריך,
  סוג מסמך, סכומים) + שורות (שם, ברקוד, מק"ט, כמות, כ.בודד, מחיר-יחידה, מחיר-ארגז, סה"כ-שורה,
  ביטחון) + ביטחון-לכל-שדה + הערות.
- **כשל = מצב, לא קריסה:** כל כשל חילוץ מסתיים בטיוטה עם הודעה בעברית ("צלמו שוב באור טוב יותר" /
  "פצלו לשתי חשבוניות" / "תשובת החילוץ לא הייתה תקינה") + כפתור "נסה שוב". השגיאה האמיתית
  נרשמת ללוג עם קוד HTTP; המשתמש רואה הודעה ידידותית. אף פעם לא 500.
- **קֶשֶר (caching):** הפרומפט המערכתי זהה בכל בקשה ונשלח עם `cache_control: ephemeral`, כך
  שהוא נטען ממטמון. שימוש בטוקנים (input/output/cache) נרשם על הטיוטה.
- **הגנת idempotency:** טיוטה ב-`processing` צעירה מ-6 דק' → 409 (מונע לחיצה כפולה); ישנה
  יותר נחשבת ריצת-serverless שקרסה ומורצת מחדש.

### התאמת ברקוד לקטלוג (במסך הבדיקה)
- **ברקוד מלא** בקטלוג → תג "קטלוג ✓", מצרף שם קנוני.
- **ברקוד מקוצר** (ספקים מדפיסים זנב בלבד — תנובה מדפיסה `42435` ל-`7290000042435`): התאמה
  לפי סיומת (מינימום 5 ספרות), גם בעמודת הברקוד וגם בעמודת המק"ט.
- **כמה מועמדים** → דירוג לפי חפיפת-שם (Jaccard) + בונוס אם היצרן = ספק החשבונית; מאמצים
  רק אם יש מנצח ברור (ציון ≥ 0.15 ומרווח ≥ 0.12 מהשני). אחרת "מספר התאמות" עם `<select>`.
- **ביטחון לפי אורך:** 5 ספרות = 64.5% ייחודי, 7 ספרות = 99.4%. תג "ברקוד מקוצר ✓" רק מ-7 ומעלה.
- **שום דבר לא נכתב לבד** — כל התאמה היא *הצעה*, מאומצת בלחיצה בלבד. נבדק בבדיקת known-answer
  על 30 הקודים של חשבונית תנובה אמיתית.

### מודל הנתונים
- `invoice_drafts`: תמונות (JSON בסדר עמודים), `extraction` (JSON גולמי מהמודל), `normalized`
  (מאומת+ערוך עם דגלים/אזהרות), טוקנים, `invoice_id` (בעת אישור), `processing_started_at`.
- **צירוף-במקום-כפילות:** צילום של חשבונית שכבר הוקלדה **משלים** אותה (ממלא תמונה חסרה, מוסיף
  שורות רק אם אין, **לעולם לא דורס סכומים רשומים** — הפרש חוזר כאזהרה) במקום ליצור חבות כפולה.
- **הפרדת חברות מלאה** על כל נתיב (guard לכל id + בדיקת `store_id` בהעלאה).

## 3. מה **לא עובד** / חלקי / שביר (כל אחד עם הסיבה)

- 🔴 **אין למידה לפי ספק — בכלל.** כל חשבונית פוגעת באותו פרומפט+סכימה סטטיים. שגיאות שיטתיות
  לכל ספק (איזו עמודה היא ארגזים מול בודדים, איפה מספר ההקצאה, פורמט הברקוד הביתי) *מנוחשות
  מחדש בכל פעם ומתוקנות ביד בכל פעם*. **זה הפער המבני הגדול ביותר** — וזה בדיוק מה שחבילת
  הסקיל בקובץ הנלווה באה לפתור. (איתות הלמידה כבר נאסף: גולמי-מול-מתוקן + לוג ביקורת + מעקב
  אילו שדות האדם נגע בהם — פשוט אף אחד לא משתמש בו עדיין.)
- ⚠️ **החדות היא איתות האיכות היחיד.** סנוור, צל על מספרים, קצה חתוך, רזולוציה נמוכה — כולם
  עוברים כ"חד". עמוד נטוי-אבל-חד נקרא בסדר, אבל סה"כ חד-אבל-מסונוור לא — ושום דבר לא מסמן זאת.
- ⚠️ **HEIC לא נתמך מחוץ ל-Apple.** iPhone HEIC שנבחר באנדרואיד/דסקטופ לא ניתן לפענוח ונדחה
  (עם הודעה ברורה) — חיכוך אמיתי בשטח.
- ⚠️ **PDF דחוס (1.5+) נספר כ-0 עמודים ועוקף את מכסת ה-8 עמודים.** רק מכסת ה-20MB ו-`max_tokens`
  מגנים מפני חשבון-טוקנים גדול. (עמוד PDF עולה 1,500–3,000 טוקני-טקסט *מעבר* לתמונה — לכן
  צילום מהאפליקציה עדיף על העלאת PDF, וה-UI מכוון לכך.)
- ⚠️ **תקרת 16 השדות המאוחדים היא מלכודת סמויה.** הוספת *כל* שדה מאפשר-null מפילה כל סריקה
  ב-`400` לפני שהיא מגיעה למודל. הפתרון הקיים: שדות טקסט הם מחרוזות רגילות (`""` = "לא קיים"),
  רק מספרים נשארים מאפשרי-null → 8 איחודים בלבד. יש בדיקה שסופרת ונופלת מעל 16, אבל התקרה
  (16) היא מגבלת-API חיצונית לא-מתועדת. **אין להוסיף שדה לסכימה בלי לבדוק זאת.**
- ⚠️ **קוד 5 ספרות ייחודי רק ~64.5%.** מתחת ל-7 ספרות זו הצעה שדורשת אישור אדם; כשאין חפיפת-שם
  בין המועמדים זה נשאר "מספר התאמות" ודוחף עבודה לאדם.
- ⚠️ **הפרש סכום בצירוף הוא רק אזהרה.** אם סה"כ הצילום שונה ב->1₪ מהחשבונית הרשומה — הרשום
  קובע, והתיאום על האדם. מכוון, אבל שקט אם הבודק מדלג.
- ⚠️ **חילוץ-מחדש מוחק עריכות.** תיקוני אדם נדרסים על ידי חילוץ טרי.
- ⚠️ **אין שליטת temperature/thinking על opus-5** (שניהם נדחים) — הדטרמיניזם הוא מה שהמודל
  נותן ב-`effort: medium`.
- 🧹 **בדיקות "סורק" מיושנות** עדיין בודקות DOM שהוסר (`scanVideo`, `btnShutter`, "מצב אבחון").
  הן עוברות רק כי בסביבת הבדיקה אין מפתח API והדף קופץ להודעת "לא מוגדר" לפני האסרטים המתים —
  **עם מפתח API ב-CI הן ייכשלו.** צריך לנקות אותן.
- 🧹 **מסמך התקלות מפגר:** §2 ו-§5 בו עדיין מספרים על הסורק האוטומטי (OpenCV) כאילו חי — הוא
  הוסר. זה יומן היסטורי, אבל קורא עלול לטעות. לאמת תמיד מול `scan-capture.js`.

## 4. מה **הוסר** מול מה שיש היום

| הוסר (הסורק האוטומטי, OpenCV) | קיים היום |
|---|---|
| viewfinder חי (`getUserMedia`) | מצלמת ה-OS (`capture="environment"`) |
| זיהוי קצוות + חיתוך + יישור פרספקטיבה | ללא חיתוך; העמוד השלם נשלח |
| צילום-אוטומטי (auto-shutter) | צילום ידני של המשתמש |
| הורדת WASM של 10MB + service-worker cache | ללא תלות כבדה |
| הקלות CSP (`wasm-unsafe-eval`, `connect-src data:`) | CSP מהודק (נבדק שההקלות הוסרו) |
| מסך אבחון | סינון חדות פשוט בקנבס |

הסיבה: צילום OS פשוט נמדד כקלט טוב יותר, בלי המורכבות והעלות של הסורק.

## 5. מספרי מפתח (לזכור)

| פרמטר | ערך | מקור |
|---|---|---|
| סף חדות | `SHARP_MIN = 0.25` (מזהיר, לא חוסם) | `scan-capture.js` |
| קצה ארוך מקסימלי | 1800px (מנוף העלות העיקרי) | `config.ai.scanMaxEdge` |
| תקרת שדות מאוחדים בסכימה | **16** (יש 8; אל תעברו) | מגבלת API |
| מקס' עמודים / גודל | 8 עמודים · 10MB לקובץ · 20MB סה"כ | config + service |
| חיוב תמונה | ‎⌈w/28⌉×⌈h/28⌉ טוקנים (צבע/איכות לא משנים) | מודל התמחור |
| עלות PDF נוספת | 1,500–3,000 טוקן/עמוד מעבר לתמונה | `pdfPages.js` |
| ייחודיות ברקוד מקוצר | 5 ספ' 64.5% · 7 ספ' 99.4% | `catalog-identify` |
| מודל חילוץ | `claude-opus-5` (env: `EXTRACT_MODEL`) | `config.ai` |
| מפתח API | `ANTHROPIC_API_KEY` (ריק → חילוץ כבוי, 503) | `config.ai` |

## 6. העיקרון שלא משתנה

**המערכת לעולם לא כותבת נתון כספי בלי שאדם אישר.** האימות מסמן ומזהיר — אך לעולם לא דוחה
או כותב לבד. כל הצעת קטלוג היא הצעה. זה חוזה העיצוב, וכל הרחבה (כולל למידה-לפי-ספק) חייבת
לשמור עליו.
