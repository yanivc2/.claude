# החילוץ — מתמונה ל-JSON מובנה

## הזרימה

```
העלאה ──► טיוטה (uploaded) ──► /process ──► Claude ──► נרמול ──► needs_review ──► אישור אדם ──► חשבונית
```

**טיוטה היא לא כסף.** שום דבר לא נכתב לטבלת החשבוניות עד שאדם לוחץ "אשר". כשל הוא *מצב*
ולא חריגה: סירוב, חשבונית ארוכה מדי, שגיאת API או תמונות כבדות מדי — כולם מסתיימים ב-`failed`
עם הודעה בעברית ובכפתור "נסה שוב".

## הקבצים

| קובץ | תפקיד |
|---|---|
| `src/ai/claude.js` | הסכימה, ההנחיות, ובניית הבקשה |
| `src/lib/extractValidate.js` | **טהור** — נרמול ואימות, בלי DB ובלי רשת |
| `src/services/scan.js` | ה-DB, קריאת ה-API, והמעבר לחשבונית |
| `src/lib/supplierMatch.js` | התאמת שם הספק לרשומה קיימת |

ההפרדה הזו מכוונת: כל הכללים העסקיים יושבים במודול טהור שאפשר לבדוק בלי מסד נתונים ובלי רשת.

## הסכימה — ומגבלה שחשוב להכיר

הבקשה משתמשת ב-structured outputs: המודל **חייב** להחזיר JSON שתואם לסכימה.

> ⚠️ **ל-API יש תקרה של 16 שדות "מאוחדים"** (כלומר `["string","null"]` או `anyOf`).
> חצינו אותה פעם אחת וכל הסריקות נפלו ב-400 — הבקשה בכלל לא הגיעה למודל.

לכן: **שדות טקסט הם מחרוזות רגילות**, ו-`""` פירושו "לא קיים". שדות מספריים נשארו
מאפשרי-`null` בכוונה — 0 היא כמות אמיתית, וערך-דמה שם היה משבש מחיר. `str()` בוולידטור ממפה
`""` ל-`null`, כך שהמעבר הזה לא שינה שום התנהגות.

יש בדיקה אוטומטית שסופרת את השדות המאוחדים ונופלת מעל 16.

## מטמון ההנחיות

`SYSTEM_PROMPT` נשלח עם `cache_control: ephemeral` והוא **זהה בייט-בייט בכל בקשה**.
לכן אסור שייכנס אליו שום דבר שמשתנה בין בקשות — תאריך, מזהה, סכום, או הנחיות ספציפיות לספק.
מידע כזה נכנס להודעת המשתמש, שהיא קטנה וממילא לא ממוטמחת.

ניצול המטמון נרשם ביומן הפעולות תחת `scan.extract`.

## הכללים שנשלחים למודל

התמצית (הנוסח המלא ב-`src/ai/claude.js`):

1. **כסף** — שקלים עשרוניים כמספרים, בלי ₪ ובלי פסיקי אלפים
2. **ערך מוחלט תמיד**, גם בזיכוי — הסימן נגזר מסוג המסמך בשרת
3. **תאריכים** — בישראל היום קודם: `DD/MM/YYYY` → `YYYY-MM-DD`
4. **מספר הקצאה** — בדיוק 9 ספרות ליד המילים "מספר הקצאה", אחרת כלום
5. **ברקוד ≠ מק"ט** — לעולם לא להעתיק אחד לשני
6. **עמודות כמות** — `quantity` היא העמודה הראשית (לעיתים ארגזים); `unit_quantity` היא
   עמודת היחידות הבודדות ("כ.בודד")
7. **מחירים** — `unit_cost` הוא ליחידה בודדת אחת. מחיר לארגז הולך ל-`pack_cost`, והשרת מחשב
8. **לא לנחש** — ערך לא קריא חוזר ריק עם ביטחון `low`. **מספר שגוי גרוע בהרבה מחסר**

## הנרמול והדגלים

הוולידטור לא דוחה מסמכים — הוא **מסמן**. כל בעיה הופכת לדגל ולהודעה בעברית, ואדם מחליט.

| קבוצה | דוגמאות |
|---|---|
| ספק | `no_supplier_match`, `fuzzy_match` |
| שדות | `missing`, `low_confidence`, `invalid_format`, `defaulted` |
| חשבון | `vat_mismatch`, `vat_rate_off`, `lines_sum_mismatch` |
| שורה | `computed`, `computed_per_unit`, `missing_amounts` |
| קטלוג | `catalog_match`, `catalog_suffix_match`, `catalog_ambiguous`, `barcode_invalid` |
| כפילות | `dup_allocation`, `dup_number`, `dup_draft` |

הכסף נשמר כ**אגורות שלמות** — לעולם לא כמספר עשרוני.

## מה קורה כשזה נכשל

| מצב | מה רואים |
|---|---|
| סירוב של המודל | "נסו לצלם שוב באור טוב יותר" |
| חשבונית ארוכה מ-`max_tokens` | "פצלו את הצילום לשתי חשבוניות" |
| שגיאת API | ההודעה כוללת **את קוד ה-HTTP** — 400 / 401 / 529 דורשים תגובות שונות לגמרי |
| מפתח לא תקין | הודעה שאומרת במפורש שהמפתח שגוי או פג |

**כל שגיאת API נרשמת ליומן השרת** עם השם, הקוד, הסוג וההודעה. בלי זה כשל נראה לבעלים
כמשפט גנרי אחד ולא ניתן לאבחון — זה בדיוק מה שקרה, וזה מה שתיקן את זה.
