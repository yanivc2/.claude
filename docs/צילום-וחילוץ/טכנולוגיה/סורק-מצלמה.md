# הסורק — איך הטלפון מצלם ומיישר חשבונית

הכול רץ בדפדפן. אין אפליקציה להתקין, ואין עיבוד תמונה בשרת.

**קובץ אחד מכיל את הכול:** `src/public/scan-capture.js`.
`src/views/scan/capture.ejs` הוא רק תגיות HTML.

## הצינור

```
getUserMedia ──► <video> ──► עותק קטן 480px ──► OpenCV ──► שערים ──► צילום ──► יישור ──► JPEG
                     │                          זיהוי      3 תנאים    מלא      warp     1800px
                     └──► ציור המרובע על הקנבס העליון
```

הזיהוי רץ ~8 פעמים בשנייה על עותק ברוחב 480 פיקסלים — לא על הפריים המלא. הרזולוציה המלאה
נוגעים בה רק ברגע הצילום.

### שלבי הזיהוי (OpenCV)

`cvtColor` → מדידת חדות (`Laplacian` + `meanStdDev`) → `GaussianBlur` → `Canny` →
`morphologyEx(CLOSE)` → `findContours` → `approxPolyDP` → המרובע הקמור הגדול ביותר.

מדידת החדות נעשית **לפני** הטשטוש — אחרת היינו מודדים את הטשטוש שלנו.
`morphologyEx(CLOSE)` סוגר פערים קטנים, כדי שקצה שנשבר בגלל בוהק תאורה עדיין ייסגר למתאר.

## שלושת השערים לפני הצילום האוטומטי

| שער | מה נמדד | סף | למה |
|---|---|---|---|
| **שטח** | אחוז הפריים שהמרובע תופס | 18% | דף רחוק מדי לא ייקרא |
| **חדות** | שונות הלפלסיאן | 45 | **זו התשובה ל"פוקוס"** — עובד גם באייפון |
| **יציבות** | תזוזת פינה מול הצורה המוחלקת | 4.5% מהאלכסון | תזוזת יד, לא רעש חישובי |

כל השלושה צריכים להתקיים ב-3 פריימים רצופים (~0.4 שניות). פריים רע **מוריד את המונה באחד**
במקום לאפס אותו — רעש חולף לא הורס רצף.

> **למה מוחלק ולא גולמי:** `approxPolyDP` מחשב מחדש את הפינות בכל פריים, אז פינה קופצת כמה
> פיקסלים גם כשהטלפון על שולחן. מדידה של הרעש הזה מול סף צר גרמה לכך שהצילום האוטומטי כמעט
> לעולם לא נורה. הפרטים ב-[`מחקרים/תקלות-ופתרונן.md`](../מחקרים/תקלות-ופתרונן.md).

## יישור הפרספקטיבה

הפינות ממוינות (שמאל-עליון, ימין-עליון, ימין-תחתון, שמאל-תחתון), הגודל נגזר מאורכי הצלעות
עצמן כדי לשמור על יחס הדף האמיתי, ו-`warpPerspective` מיישר **ישירות לגודל הסופי** —
דגימה מחדש אחת במקום שתיים.

## מה תלוי במכשיר

| יכולת | היכן עובד | ההתנהגות אצלנו |
|---|---|---|
| `focusMode: continuous` | Chrome/אנדרואיד | מופעל רק אם `getCapabilities()` מדווח עליו |
| `torch` (פנס) | Chrome/אנדרואיד | הכפתור מוצג רק אם נתמך |
| `getUserMedia` | הכול (בהקשר מאובטח) | בלעדיו — נפילה למצלמת המכשיר |
| מדידת חדות | **הכול, כולל אייפון** | ולכן היא השער האמיתי נגד טשטוש |

## שרשרת הנפילה

הסורק אף פעם לא הדרך היחידה לצלם:

1. הכול עובד → סורק אוטומטי מלא
2. OpenCV לא נטען → מצלמה חיה + כפתור "צלם" ידני, בלי חיתוך אוטומטי
3. אין הרשאת מצלמה / אין `getUserMedia` → `<input capture="environment">` — מצלמת המכשיר
4. תמיד → בחירת קבצים מהגלריה או PDF

## OpenCV.js — 10MB, וההתמודדות איתם

- מאוחסן אצלנו ב-`public/vendor/opencv.js` (גרסה 4.9.0). CSP חוסם CDN, ולכן חייב להיות מקומי.
- ~3.2MB ברשת אחרי דחיסת brotli.
- **נטען רק כשפותחים את המצלמה**, לא בטעינת הדף.
- **לא עובר דרך ה-Service Worker** — זה תקע את iOS. מטמון ה-HTTP (`immutable, max-age=30d`)
  נותן את ההורדה החד-פעמית.
- CSP דורש `'wasm-unsafe-eval'` ו-`connect-src data:`.

## דברים שקל לשבור כאן

- **סדר העמודים** חייב להיתפס לפני הפענוח האסינכרוני, אחרת עמודים מתחלפים.
- **EXIF** — חובה `createImageBitmap(file, { imageOrientation: 'from-image' })`, אחרת צילומי
  אנדרואיד מגיעים בשכיבה.
- **ניהול זיכרון** — לכל `Mat` שנוצר ב-OpenCV.js חייב להיות `delete()`.
- **מיפוי הקנבס העליון** חייב לחשב את שני הצירים; `object-fit: cover` חותך ציר אחד.
