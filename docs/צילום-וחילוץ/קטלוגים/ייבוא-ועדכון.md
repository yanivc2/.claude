# ייבוא ועדכון של הקטלוג

הייבוא **אף פעם לא מוחק**. הוא מוסיף ברקודים חדשים ומעדכן קיימים. אפשר להריץ אותו שוב ושוב
בבטחה, וכל ריצה מדווחת `נוספו / עודכנו / ללא שינוי`.

## דרך 1 — GitHub Action (שופרסל, בלחיצה אחת)

`Actions` ← **AP Control Catalog Import** ← `Run workflow`.

- שדה `stores`: מספרי סניפים מופרדים בפסיק. ברירת המחדל `5,18`.
- רץ גם אוטומטית **כל יום ראשון ב-04:00 UTC**.
- משתמש באותו secret של הגיבוי (`DATABASE_URL`), כך שאין מה להגדיר.
- הקובץ המחולק לפי יצרנים נשמר כ-artifact להורדה.

> **אל תוסיף סניפים סתם.** נמדד: הסניף השני מוסיף ~1,400 ברקודים, כל אחד אחריו מוסיף ~200.
> שני סניפים מספיקים. הפירוט ב-[`מקורות-נתונים.md`](מקורות-נתונים.md).

## דרך 2 — העלאת קובץ בהגדרות

**הגדרות ← 🏷️ טעינת קטלוג-על.** לקובץ CSV/XLSX משלך. הכותרות הנתמכות:
`ברקוד, שם, מקט, יצרן, יח' אריזה, כמות, יחידת מידה, מחיר מדף` — וגם עמודת מחיר לכל רשת
(`מחיר שופרסל`, `מחיר רמי לוי`, `מחיר טיב טעם`, `מחיר קרפור`), שמהן נשמר החציון.

עמודות נוספות בקובץ פשוט לא נקראות — אפשר להעלות את הקובץ כמו שהוא, בלי לערוך אותו.

**XLSX מקורי עדיף על CSV.** אקסל מוריד אפסים מובילים מהברקודים בשמירה ל-CSV
(‎012345… → ‎12345…). המערכת מתקנת את זה לפי ספרת הביקורת ומדווחת כמה תוקנו, אבל XLSX
לא עובר את ההמרה הזו בכלל. הסיפור המלא ב-[`מחקרים/תקלות-ופתרונן.md`](../מחקרים/תקלות-ופתרונן.md).

### אין מגבלת גודל, אבל יש סיפור מאחורי זה

Vercel חוסמת כל בקשה שגופה גדול מ-**4.5MB** — ברמת הפלטפורמה, לפני שהקוד של האפליקציה
בכלל רץ. קובץ ארבע הרשתות שוקל 5.8MB, ולכן ניסיון ההעלאה הראשון חזר כדף
`413 FUNCTION_PAYLOAD_TOO_LARGE` באנגלית, בלי שום זכר לזה בלוגים. המגבלה הזו לא ניתנת
להגדלה, ולא משנה מה `multer` מרשה.

לכן **הקובץ נקרא בדפדפן** (`src/public/catalog-upload.js`): הדפדפן פותח את ה-ZIP בעצמו
(`DecompressionStream`), זורם על הגיליון וחותך אותו בכל `</row>`, ושולח לשרת ~2,000 שורות
בכל בקשה. במדידה על 82,371 שורות: **42 בקשות, הגדולה שבהן 178KB** — פי 26 מתחת למגבלה.
בזמן הטעינה מוצג פס התקדמות אמיתי.

אם הטעינה נעצרת באמצע (רשת) — פשוט טוענים שוב את אותו קובץ. הייבוא הוא upsert, אז מה
שכבר נכנס פשוט יעודכן.

> קריאת ה-XLSX קיימת **פעמיים**: `src/lib/xlsxRead.js` בשרת ו-`src/public/catalog-upload.js`
> בדפדפן. `test/catalog-upload.test.js` מזין לשתיהן את אותו קובץ ומוודא שהתוצאה זהה — זה מה
> ששומר עליהן מלהיפרד.

## דרך 3 — שורת פקודה (למפתח)

```bash
DATABASE_URL=<neon> npm run catalog:import
DATABASE_URL=<neon> npm run catalog:import -- --stores 5,18,1,2
DATABASE_URL=<neon> npm run catalog:import -- --url <קובץ.gz>
```

בלי `DATABASE_URL` זה רץ מול ה-SQLite המקומי. הכלי לא רץ בתוך Vercel לעולם.

## אחרי שינוי סכימה

הוספת עמודה למסד **לא קורית לבד** בענן. אחרי פריסה שכוללת עמודה חדשה:

**הגדרות ← "עדכון מסד נתונים"** — פעם אחת. בטוח, לא מוחק כלום.

בלי זה, פעולות שנוגעות בעמודה החדשה יחזירו שגיאה.

## איך יודעים שזה עבד

1. `/products/master` — מציג את מספר הפריטים ואת רשימת היצרנים
2. בסריקה — שורות מזוהות מקבלות תג `קטלוג ✓` או `ברקוד מקוצר ✓`
3. ביומן ה-Action — ספירה לכל סניף ועשרת היצרנים הגדולים

## מה עלול להיכשל

| תסמין | הסיבה הסבירה |
|---|---|
| "לא נמצאו קבצי PriceFull" | מבנה הפורטל השתנה — אפשר לעקוף עם `--url` |
| כל המוצרים "ללא יצרן" | שם התג בקובץ שונה. הפענוח מקבל `ManufacturerName` וגם `ManufactureName` |
| `נוספו 0` בלי שגיאה | לשורות אין ברקוד. שורה בלי ברקוד נדלגת — הברקוד הוא מפתח הזהות |
| הייבוא רץ אבל `/products/master` ריק | הייבוא רץ מול מסד אחר. לוודא ש-`DATABASE_URL` מצביע ל-Neon |
| `413 PAYLOAD_TOO_LARGE` בהעלאה | דפדפן ישן בלי `DecompressionStream`, שנפל למסלול הישן. לפתוח מ-Chrome/Safari עדכני |
| "מסד הנתונים עדיין לא עודכן" | הפריסה הוסיפה עמודה. **הגדרות ← עדכון מסד נתונים**, ואז לטעון שוב |
