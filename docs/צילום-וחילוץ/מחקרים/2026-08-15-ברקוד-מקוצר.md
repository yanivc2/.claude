# מחקר: הקוד המודפס בחשבונית הוא ברקוד מקוצר

**תאריך:** 15.08.2026 · **סטטוס:** אומת ומיושם

## השאלה

חשבונית תנובה אמיתית (31 שורות) הגיעה עם עמודת `קוד` שמכילה מספרים כמו `42435`, `16930695`,
`4136857` — ובלי שום ברקוד. קטלוג-העל מזהה רק לפי ברקוד, ולכן הוא לא עזר בכלל.

הבעלים אמר: **"זה כן ברקוד, רק מקוצר."**

## הבדיקה

בדקנו את 31 הקודים מהחשבונית מול קובץ קטלוג של 38,279 ברקודים, בארבע צורות התאמה:
זהות מלאה, סיומת, סיומת בהתעלם מספרת ביקורת, והכלה.

```
exact barcode == code      :  1/31
barcode ENDS WITH code     : 30/31   ← זה
ends with code (skip check):  1/31
barcode CONTAINS code      : 30/31
```

הקוד היחיד שלא נמצא כסיומת (`72961544`) הוא בעצמו ברקוד EAN-8 מלא בקטלוג. כלומר
**31 מתוך 31 נפתרו**, וכל אחד למועמד יחיד.

## מה זה אומר

ברקוד ישראלי הוא `729` + 10 ספרות. הספק מדפיס את **הזנב** בלבד, בלי התחילית ובלי אפסים מובילים.
זה עקבי לחלוטין בחשבונית שנבדקה.

## ההחלטה

**סף 5 ספרות** — לא 6.

השיקול הראשוני היה 6, כי הדו-משמעות באורך 5 גבוהה פי כמה. אבל זה היה שגוי מטעם פשוט:
החשבונית האמיתית מדפיסה קודים בני 5 ספרות (`42435`, `43890`, `44248`). סף 6 היה פוסל בדיוק
את המקרים שהמחקר הזה בא לפתור.

הסיבה שאפשר: **הדו-משמעות מטופלת ולא מנוחשת.** כשיש כמה מועמדים, כולם חוזרים והמסך מציג רשימת
בחירה. באורך 4 אין מה לבחור — 90% מהקודים יהיו דו-משמעיים.

## מה יושם

- `lookupByCodes()` ב-`src/services/masterCatalog.js` — שאילתה אחת לכל טיוטה
- הקוד נבדק גם מעמודת הברקוד וגם מעמודת המק"ט
- דגלים `catalog_suffix_match` (מועמד יחיד) ו-`catalog_ambiguous` (כמה)
- כפתור **"אמץ ברקוד ושם"** ובורר מועמדים במסך הבדיקה
- **שום דבר לא נכתב לבד** — הכל הצעה שאדם מאשר

## מה זה פותח

זה משנה את התמונה למשפחה שלמה של ספקים, לא רק לתנובה. כל ספק שמדפיס קוד פנימי שהוא סיומת
של ברקוד — וזה נפוץ — הופך פתאום לניתן לזיהוי מלא. זו גם ההנחיה הראשונה שתיכנס לפרופיל הספק
של תנובה.
